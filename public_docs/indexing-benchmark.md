# Бенчмарк индексации документов

Среднее по 10 последовательным запросам каждого типа; секунды на документ.

| Этап | Вакансия | Резюме |
|---|---:|---:|
| Извлечение сущностей LLM и проверка цитат | 7,525 | 9,693 |
| Эмбеддинг | 1,167 | 1,941 |
| Запись вектора в Milvus | 0,781 | 0,555 |
| BM25 | 0,038 | 0,000184 |
| **Итого без LLM** | **1,987** | **2,496** |
| **Итого с LLM** | **9,512** | **12,189** |
| **Стоимость LLM, $/документ** | **0,001364** | **0,001442** |
| Стоимость / число принятых сущностей, $ | 0,0000395 | 0,0000379 |

| Условия | Значение |
|---|---|
| Выборка | 3 вакансии и 6 синтетических резюме с повторами |
| LLM | `deepseek/deepseek-v4.1-flash-1017`, OpenRouter, `wafer/us` |
| Эмбеддинг | `google/embeddinggemma-2`, CPU FP32, 128 измерений |
| Сервер | 6 vCPU Intel Xeon Gold 6230R; модель загружена заранее |
| Кэш | Эмбеддинги вычислены заново; `cached_tokens=0` у всех 20 ответов |

Стоимость на сущность — отношение стоимости документа к числу принятых сущностей, а не отдельный тариф. BM25 для вакансии — полное перестроение индекса на 21 документе с обычным IDF, без словаря Malt; для резюме — подготовка токенов запроса. Это не инкрементальное добавление и не замер поиска. Запись вектора резюме измеряется отдельно для эксперимента: текущему retrieval-пайплайну она не требуется. Маленькая повторная выборка не представляет production-нагрузку; время и стоимость новых запусков будут отличаться.

## Воспроизведение

Нужны Python ≥ 3.12, зависимости проекта с extra `embeddings`, локальный Milvus на `127.0.0.1:19530`, доступ к весам модели и `OPENROUTER_API_KEY`. Настройки — `configs/indexing_benchmark.yaml` и `configs/llm.yaml`. **Запуск выполняет платные запросы:** по умолчанию 10 вакансий и 10 резюме. Исторические данные были собраны из hash-проверенных вакансий кейса и синтетических резюме; приватные резюме в API не передаются.

Для воспроизведения BM25-условий используется `public_data/mfti_matching_gt` с манифестом и извлечениями 20 вакансий. Несмотря на имя директории, набор содержит обработанные реальные резюме и предназначен для приватного репозитория; полная анонимность не гарантирована. Также требуется настроенный Milvus; пример конфигурации — `deploy/milvus/compose.yaml` и `deploy/milvus/loopback.yaml`, которым нужны локальные файлы `.data/milvus/minio.env` и `.data/milvus/user.yaml`. Не публикуйте эти файлы и токены.

Из корня проекта в первом терминале:

```bash
.venv/bin/python -m vrscore.embedding_server port=18767
```

После загрузки модели, во втором терминале:

```bash
.venv/bin/python -m vrscore.benchmarking.indexing_benchmark \
  iterations=10 output_dir=.experiments/indexing-benchmark-run
```

При повторе укажите **новый** `output_dir`: существующая директория не перезаписывается. Параметры Hydra можно менять через CLI, например `iterations=1` для проверки; это всё равно платный запуск. `results.json` содержит результаты и агрегаты по типам, `rows.json` — промежуточные записи. Бенчмарк проверяет запись в Milvus и удаляет собственную временную коллекцию. Запросы с ненулевым или неподтверждённым `cached_tokens` отмечаются ошибкой; проверяйте `summary` и статусы всех строк.
